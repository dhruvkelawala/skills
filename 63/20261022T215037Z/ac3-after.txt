$ stage 1's branch and worktree steps in skills/issue-to-pr/SKILL.md
3:1. Resolve the repository and remote, run `git fetch <remote>`, and pin the base. Standalone: `refs/remotes/<remote>/<default-branch>` and its SHA. Stacked: the top PR's head, found as [stacks](references/stacks.md) describes.
5:3. Move the build into its own T3 thread and worktree, on the branch `<type>/<issue>-<short-description>` with a conventional-commit type. The base branch is the branch of the base ref: the default branch, or for a layer the predecessor's head branch. Call `t3_worktree_status` and take the first case that fits:
6:   - **The thread is in the build's worktree**, a worktree on a branch for this issue, `<type>/<issue>-` with any type and description, as when `t3_thread_launch` or `t3_worktree_handoff` made it. Keep that branch and continue here.
7:   - **The thread is on the project's main checkout**, as when `/issue-to-pr` is typed in an existing thread. Call `t3_worktree_handoff` with `branch`, `baseRef` set to the base branch, `startFromOrigin: true`, and `continuationPrompt` set to this invocation, as the last call of the turn. The thread moves into the new worktree, and the continuation starts this stage again there. Create no branch and write no file in the main checkout.
8:   - **The thread is in another worktree**, which `t3_worktree_handoff` cannot move. Launch the build's thread as below, give the user its link as `[<title>](t3-thread://v1/<threadId>)`, and end this run.
10:   To launch a build's thread, call `t3_thread_launch` with `message` set to `/issue-to-pr <n>` and this run's flags, and `workspaceStrategy` set to `{"type": "worktree", "baseRef": "<base branch>", "branch": "<branch>", "startFromOrigin": true}`. A build started from the 10:00 report or in spec mode starts this way too.
11:4. Read `EVIDENCE.md` from the checkout. When the base predates it, read `git show origin/<default-branch>:EVIDENCE.md`. When neither exists, run `/evidence plan` for the touched surface, and say in the report that the repo should adopt `EVIDENCE.md`.
16:9. Put the branch at `base_sha`. When `git log --oneline <base_ref>..HEAD` prints nothing, the branch has no commits of its own, so when `HEAD` differs from `base_sha`, move it with `git reset --keep <base_sha>`. When it prints commits, the branch holds an earlier attempt: leave it, record `blocked: branch has earlier commits`, and ask the user. For a layer, record `stack_tracking` as [stacks](references/stacks.md) says.
18:**Complete when:** this thread is in the build's worktree, the run record holds the work item, mode, base ref and SHA, branch and contract, and the branch is checked out at `base_sha`.
$ resume step 1 in skills/issue-to-pr/references/resume.md
5:1. Work on the recorded branch, in the worktree that has it checked out (`git worktree list`). When `t3_worktree_status` shows this thread in that worktree, continue here. When another worktree has it, call `t3_thread_launch` with `workspaceStrategy` set to `{"type": "existing_worktree", "worktreePath": "<path>", "branch": "<branch>"}` and `message` set to `/issue-to-pr <n> resume`, give the user its link, and stop. When no worktree has it, record `blocked: branch not selectable` and stop, before any repair. Never switch this thread's checkout to the branch. Then `git status` must be clean and `HEAD` must equal the recorded head or the PR's `headRefOid`.
